Fix silence generation by adding silence tokens to training data

Problem:
- Preprocessing was filtering out silence intervals from TextGrid alignment
- Espeak-ng phonemization never produces explicit <sil> tokens
- Result: Model never trained on silence → can't generate silence boundaries
- Symptoms: Words run together, silence frames missing/stretched

Changes:
1. preprocess.py: Add _align_phonemes_with_textgrid() to insert <sil> tokens
   - Aligns espeak phonemes with TextGrid intervals (speech + silence)
   - Preserves silence intervals that were previously filtered out
   - Utterances now include silence tokens at proper positions

2. model/fastspeech2.py: Add masked_l1_silence_weighted() loss function
   - Detects silence frames by low energy (< -0.5)
   - Weights silence loss 2x higher to prevent gradient dilution
   - Applied to mel_after L1 loss for better silence learning

3. train_fastspeech.py: Use silence-weighted loss in training loop
   - Passes energy_gt to loss function for silence detection
   - Stronger gradient signal for silence frames during backprop

4. regenerate_phonemes.py: New script to regenerate phoneme/duration only
   - Reuses existing mel/f0/energy (only updates phoneme + duration)
   - Much faster than full preprocessing (minutes vs hours)
   - Parallelized across CPU cores

Impact:
- ~12,910 utterances now have silence tokens inserted
- Utterance length increase: ~10-15% (still within 2048 pos encoding limit)
- Fine-tune from best.pt to learn silence with stronger gradients
- Expected: Clear silence boundaries, no word stretching, proper mel silence regions

Training:
- Continue from best.pt checkpoint (all representations transfer)
- Model learns silence patterns quickly via silence-weighted loss
- Estimated convergence: ~50-100k steps
- No retraining from scratch needed
